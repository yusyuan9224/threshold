How it works

Three steps. No middle ground.

Threshold is built as a strict pipeline — raw Bluetooth signal never touches the lock screen directly. Presence is inferred, evidence is weighed, and only then is a system effect requested and confirmed.

01 — SENSE
Presence Detection
Reads your trusted device's Bluetooth advertisements. Observation only — Threshold never connects to your phone.
→
02 — DECIDE
Automatic Protection
When the evidence says you've left, Threshold requests a lock — then confirms the screen actually locked before it calls it done.
→
03 — HAND OFF
Native Authentication
When you're back, Threshold wakes the display and steps aside. Touch ID, Apple Watch, or your password — always typed by you, on macOS's own screen.
Design principles

Built to fail closed, not fail open.

Most Bluetooth-proximity tools reach for whatever gets the job done fastest — an active connection, a private framework, synthesized keystrokes. Threshold takes the narrower path on purpose.

Observation only

Threshold reads your trusted device's Bluetooth advertisements — the same kind of signal your AirPods use to show a battery level — and never opens a connection. Your phone never even sees this Mac.

CoreBluetooth · scanForPeripherals, no connect()

Never handles your password

Not stored, not typed, not simulated. Authentication is always handed back to macOS.

Fails closed

Uncertain sensor health or thin evidence means Threshold does nothing. It never guesses that you've left.

No cloud, no account

Everything runs on this Mac. Nothing to sign up for, nothing sent anywhere.

Evidence, not assertions

Every claim on this page is backed by a real-device measurement checked into the repo — not a marketing line.

  • 01
    Domain owns temporal rules, never time itself.

    The decision logic is pure and clock-free — every real-world timestamp comes from the edges, so the core is exhaustively testable.

  • 02
    Absence of evidence is not evidence of absence.

    A dropped Bluetooth signal from a dead radio looks nothing like a departed device to Threshold — and never gets treated as one.

  • 03
    A device is supported only if it can be observed reliably through supported APIs.

    No private frameworks. If it isn't documented and it isn't measured, it isn't in the supported list.

Honest status — 2026-09-03

This is a beta. Here's exactly what that means.

The primary path — an iPhone as your trusted device, Auto Lock, Wake on Return, Touch ID and Apple Watch native unlock — has been verified end to end on real hardware, including a full departure→lock→return→wake cycle. What's still open:

  • Code signing & notarization — not yet available; build from source with scripts/make-app-bundle.sh until a signed release exists.
  • Apple Watch & iPad are supported as secondary devices, but Apple Watch specifically loses reliable range past ~8 m — pair it with a phone, don't rely on it alone.
  • Trademark clearance for the name "Threshold" is still pending — it may change before a stable v1.0.
  • The full device-observability matrix (reboot, re-pairing, generic beacons) is partially measured.
